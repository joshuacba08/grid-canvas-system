<DocsSection id="redraw-lifecycle" index="04" title="Redraw lifecycle">
  <p>
    Animated scenes follow a small, explicit cycle. Rendering stays deterministic and
    each helper protects itself from context state left behind by another draw call.
  </p>
  <ol class="docs-steps">
    <li>
      <span>01</span>
      <strong>Update</strong>
      <p>Advance state with elapsed seconds.</p>
    </li>
    <li>
      <span>02</span>
      <strong>Clear</strong>
      <p>Reset the frame and redraw the grid.</p>
    </li>
    <li>
      <span>03</span>
      <strong>Draw</strong>
      <p>Render sprites, shapes and overlays.</p>
    </li>
  </ol>
</DocsSection>

<DocsSection id="pixel-sprites" index="05" title="Pixel sprites">
  <p>
    A sprite is a readonly array of equal-length strings. Each character maps to a
    palette value; transparent entries reserve space without drawing a pixel. Compile
    repeated sprites once with <code>compilePixelSprite()</code>, then render them with
    <code>drawCompiledPixelSprite()</code> inside animation loops.
  </p>
  <CodeBlock snippet={docsSnippetMap.sprite} />
  <div class="docs-rule-grid">
    <div>
      <strong>x / y</strong>
      <span>Absolute canvas coordinates</span>
    </div>
    <div>
      <strong>pixelSize</strong>
      <span>Positive logical pixel size</span>
    </div>
    <div>
      <strong>palette</strong>
      <span>Every character must be defined</span>
    </div>
  </div>
</DocsSection>

    but still classified as Experimental.

<DocsSection id="framework-cleanup" index="15" title="Framework cleanup">
  <p>
    In React, Angular, Vue, Astro islands or any component system, create the runtime
    only after the canvas element exists and call <code>destroy()</code> from the
    framework cleanup hook. Keep every unsubscribe returned by pointer, animator and
    machine subscriptions next to that cleanup path.
  </p>
</DocsSection>

<DocsSection id="game-architecture" index="16" title="Build a small game">
  <p>
    A playable scene is the same explicit redraw cycle with four connected
    responsibilities. Read input first, advance simulation with elapsed seconds, resolve
    collisions, then draw the resulting state. For menu, game, pause and game-over
    flows, keep scene transitions in <code>createSceneManager()</code>; for maze-like
    worlds, use the tilemap helpers under <code>GridCanvasSystem.runtime</code>.
  </p>
  <div class="docs-game-cycle" aria-label="Small game architecture">
    <div>
      <span>01</span>
      <strong>Input</strong>
      <small>Track keys, pointer or touch.</small>
    </div>
    <div>
      <span>02</span>
      <strong>Update</strong>
      <small>Move actors using elapsed time.</small>
    </div>
    <div>
      <span>03</span>
      <strong>Resolve</strong>
      <small>Apply collisions, score and rules.</small>
    </div>
    <div>
      <span>04</span>
      <strong>Render</strong>
      <small>Clear once, then draw world and HUD.</small>
    </div>
  </div>
  <CodeBlock snippet={docsSnippetMap.gameLoop} />
  <p>
    Keep the game model in ordinary objects and arrays. Runtime helpers coordinate time
    and input; drawing helpers visualize the current model. This keeps pause, restart
    and win states readable instead of burying them inside rendering code.
  </p>
